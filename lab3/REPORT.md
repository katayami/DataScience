# Отчёт по лабораторной №3: линейные модели

## 1. Данные и подготовка

### Student_Performance.csv (регрессия)
- 10 000 строк, 5 признаков, целевая переменная — `Performance Index`.
- `Extracurricular Activities` переведён в число: `Yes → 1`, `No → 0`. Остальные признаки уже числовые, пропусков нет.
- Разбиение: `train_test_split(test_size=0.2, random_state=42)`, то есть 8000 строк в train и 2000 в test.
- **Масштабирование:** внутри `train_linear_regression` признаки стандартизуются (z-score) по среднему и стандартному отклонению **только train-части**, так что утечки из test нет. Без этого `Previous Scores` (диапазон 40–99) и бинарный признак имеют очень разный масштаб, и при `lr = 0.05` градиентный спуск расходится. После обучения веса пересчитываются обратно в исходные единицы признаков: `w = w_s / σ`, `b = b_s − Σ w_s·μ/σ`. Поэтому модель применяется к test без отдельного шага масштабирования.

### german.csv (классификация)
- 1000 строк, 20 признаков (разделитель `;`), целевая переменная — `Creditability` (1 — хороший заёмщик, 0 — плохой).
- Классы несбалансированы: 700 / 300.
- Разбиение: `train_test_split(test_size=0.2, random_state=42, stratify=y)`, то есть 800 строк в train и 200 в test. Стратификация сохраняет долю классов 70/30 в обеих частях.
- Признаки закодированы целыми числами. В основной модели они используются как числа и стандартизуются по train так же, как в регрессии.

## 2. Гипотезы и эксперименты

**Линейная регрессия.** Пакетный градиентный спуск по MSE с параметрами по умолчанию из контракта: `learning_rate = 0.05`, `epochs = 800`, веса инициализированы нулями.
Градиент: `∂L/∂w = 2/n · Xᵀ(Xw + b − y)`.

| эпоха | MSE на train |
|---|---|
| 0 | 3428.04 |
| 10 | 421.08 |
| 50 | 4.2616 |
| 100 | 4.1697 |
| 799 | 4.1697 |

Начальная MSE примерно равна среднему квадрату целевой переменной, так как веса нулевые. После стандартизации задача хорошо обусловлена, поэтому спуск сходится примерно за 100 эпох, дальше MSE не меняется. Как проверка взят `LinearRegression` из sklearn: на тех же данных он даёт ту же test MSE (4.0826), значит, решение совпадает с аналитическим.

Веса в исходных единицах: `Hours Studied` 2.853, `Previous Scores` 1.017, `Extracurricular Activities` 0.609, `Sleep Hours` 0.477, `Sample Question Papers Practiced` 0.192, смещение −33.92.

**Логистическая регрессия.** Пакетный градиентный спуск по бинарной кросс-энтропии (BCE), `learning_rate = 0.1`, `epochs = 1000`, порог 0.5.
Градиент: `∂L/∂w = 1/n · Xᵀ(σ(Xw + b) − y)`.

| эпоха | BCE на train |
|---|---|
| 0 | 0.6931 (= ln 2) |
| 10 | 0.6127 |
| 100 | 0.4922 |
| 300 | 0.4825 |
| 999 | 0.4821 |

**Гипотеза 1:** собственная реализация совпадает с `sklearn.LogisticRegression`. Подтверждена: ROC-AUC 0.8081 против 0.8086, остальные метрики одинаковы. Небольшая разница в AUC объясняется L2-регуляризацией в sklearn (C = 1).

**Гипотеза 2:** признаки `german.csv` в основном категориальные (цель кредита, статус счёта и т. п.), поэтому их числовые коды не упорядочены по смыслу, и one-hot кодирование должно улучшить линейную модель. Подтверждена: если закодировать one-hot все признаки, кроме `Duration`, `Credit_Amount` и `Age` (получается 54 признака), собственная модель даёт ROC-AUC 0.820, Accuracy 0.800 и F1 0.861. Это дополнительный эксперимент. Основные результаты и JSON посчитаны на исходных признаках, на том же разбиении, что и для бейзлайнов.

**Бейзлайны:** `DecisionTreeClassifier(max_depth=5, random_state=42)` и `KNeighborsClassifier(n_neighbors=15)` с `StandardScaler` в pipeline. KNN чувствителен к масштабу, поэтому scaler обязателен. Глубина дерева ограничена, чтобы уменьшить переобучение на 800 объектах.

## 3. Метрики

**Регрессия (test, 2000 объектов):** MSE = **4.0826**, R² = 0.989.

**Классификация (test, 200 объектов, один и тот же split):**

| модель | ROC-AUC | Accuracy | Precision | Recall | F1 |
|---|---|---|---|---|---|
| собственная логистическая регрессия | **0.8081** | **0.770** | 0.8013 | 0.8929 | 0.8446 |
| sklearn LogisticRegression (справочно) | 0.8086 | 0.770 | 0.8013 | 0.8929 | 0.8446 |
| DecisionTree (max_depth=5) | 0.6781 | 0.690 | **0.8305** | 0.7000 | 0.7597 |
| KNN (k=15) | 0.7745 | 0.765 | 0.7719 | **0.9429** | **0.8489** |
| собственная логистическая регрессия + one-hot | 0.8200 | 0.800 | 0.8378 | 0.8857 | 0.8611 |

## 4. Выводы

- Собственная линейная регрессия на градиентном спуске сходится к тому же решению, что и МНК (test MSE 4.08, R² 0.989). Зависимость `Performance Index` от признаков почти линейная, и сильнее всего на него влияют `Hours Studied` и `Previous Scores`.
- Для градиентного спуска нужно стандартизовать признаки: при заданных `lr` без неё обучение расходится.
- **Где собственная логистическая регрессия выигрывает.** У неё лучший ROC-AUC (0.808) и лучшая Accuracy (0.770): вероятности, которые она выдаёт, лучше всего ранжируют заёмщиков. Данных немного (800 объектов), а зависимость близка к аддитивной, поэтому простая модель с низкой дисперсией обобщает лучше остальных.
- **Где проигрывает.** У KNN выше Recall (0.943) и, совсем немного, F1 (0.849 против 0.845): KNN чаще предсказывает мажоритарный класс «хороший». Из-за этого у него ниже Precision и ROC-AUC. У дерева самая высокая Precision (0.831), но по ROC-AUC (0.678) и Accuracy (0.690) оно хуже всех. Одно неглубокое дерево даёт грубые, ступенчатые вероятности и нестабильно на маленькой выборке.
- Линейную модель ограничивает то, что категориальные признаки подаются как числовые коды. С one-hot кодированием она обходит все бейзлайны по всем метрикам, кроме Recall.

## 5. Воспроизводимость

```bash
pip install numpy pandas scikit-learn
python run_experiments.py
```

- Скрипт `run_experiments.py` загружает данные, делает разбиение (`random_state = 42`, `test_size = 0.2`, стратификация для german), вызывает функции из `linear_models.py`, печатает историю потерь и метрики и записывает `experiment_results.json`.
- Собственные модели детерминированы: веса инициализируются нулями, используется полный батч.
- Версии, на которых получены результаты: Python 3.13, scikit-learn 1.8.0.
- В `experiment_results.json` раздел `own_logistic` содержит собственную модель, `logistic_regression` — `sklearn.LogisticRegression` для справки. Функция `compare_classical_models` по README возвращает в поле `logistic_regression` метрики **собственной** модели.
